# Site Initializers

`ecopulse-site-initializer` creates the EcoPulse Smart City site (`ecopulse-site`); `veridian-site-initializer` applies the City of Veridian content to the Guest site (`L_GUEST`). Both are `siteInitializer` client extensions: everything under `site-initializer/` is read by Liferay's `BundleSiteInitializer`.

## Ground rule: Liferay's format, not an invented one

`BundleSiteInitializer` silently ignores any file or key it does not know, and one bad file (e.g. a style book) rolls back the **whole** site. Before adding a new kind of content, check the path and keys against Liferay's own code or a Liferay-maintained initializer, not against other files in this repo:

- `BundleSiteInitializer.java` (`modules/apps/site-initializer/site-initializer-extender/…`) lists every resource path it reads.
- Working examples: `workspaces/liferay-learn-workspace/client-extensions/liferay-learn-site-initializer/site-initializer/` in liferay-portal.

Validate `page-definition.json` and `master-page.json` against the schemas of the Liferay version in use (`modules/apps/layout/layout-impl/src/main/resources/com/liferay/layout/internal/importer/validator/dependencies/`): invalid ones are skipped without an error in the log. Then prove every change with the **E2E Boot Test** (`tools/run-e2e-boot.sh`; PR label `e2e-boot`), which boots Liferay and checks both sites. The ordinary E2E never boots, so it cannot catch initializer errors.

## Layout (verified on DXP 2026.q1 LTS)

| What                          | Path                                                                                                     | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ----------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Documents                     | `documents/group/`                                                                                       | Never delete images here, even unreferenced ones; they are demo assets.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Fragments                     | `fragments/group/<collection>/<fragment>/`                                                               | `collection.json` (`name`, `description`); `fragment.json` with `htmlPath`/`cssPath`/`jsPath`/`configurationPath` pointing at files (a `configuration.json` without `configurationPath` is ignored). The fragment key is the folder name.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Pages                         | `layouts/<order>_<name>/page.json` + `page-definition.json`                                              | `page.json`: `friendlyURL`, `name_i18n`, `type`, `hidden`, `private`, `system`. `page-definition.json`: `pageElement` (a `Root` of `Fragment` elements, `definition.fragment.key`), `settings`, `version`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Theme CSS, favicon, spritemap | `layout-page-templates/master-pages/<key>/master-page.json` + `page-definition.json`                     | Put `themeCSSClientExtension`, `themeSpritemapClientExtension`, `favIcon` (and `styleBook.key`) in the **master page's** `settings`, each `{ "externalReferenceCode": "LXC:<client extension id>", "name": "<its name>" }` (`favIcon` **must** have `name`: without it the object matches both of the schema's `oneOf` types, the whole page definition is rejected and the master page is silently skipped), and give the master a `DropZone`. Pages then use `settings.masterPage.key`. Workspace client extensions get an `LXC:` prefix and an unknown ERC is skipped silently. The site initializer applies only `themeName`, `css` and `masterPage` from a _page's_ settings, so client extensions set on a page are ignored, and there is no layout-set-level equivalent. |
| Site logo, look and feel      | `layout-set/public/logo.png`, `metadata.json` (`themeName`, `settings`), `css.css`, `js.js`              | Nothing else in `layout-set/` is read.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Style books                   | `style-books/<brand>-style-book/style-book.json` + `frontend-tokens-values.json`                         | `style-book.json` needs `name`, `themeId` (`classic_WAR_classictheme`) and `frontendTokensValuesPath`; a missing `themeId` fails the whole site (LPD-30357). Values are `{ "<token>": { "cssVariableMapping": "…", "value": "…" } }` using token names from the Classic theme's `frontend-token-definition.json` (e.g. `primaryColor`, `secondaryColor`, `h1FontSize`).                                                                                                                                                                                                                                                                                                                                                                                                         |
| Navigation menus              | `site-navigation-menus.json`                                                                             | Array of `{ externalReferenceCode, name, typeSite, menuItems }`; items are `type: "layout"` (`friendlyURL`, `privateLayout`) or `type: "url"` (`url`, `useNewTab`), each with `name_i18n` (items without it are skipped).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Display page templates        | `layout-page-templates/display-page-templates/<key>/display-page-template.json` + `page-definition.json` | `contentType.className` `[$OBJECT_DEFINITION_CLASS_NAME:<Object>$]` (the object must exist before the initializer runs, as `ecopulse-batch` ensures under LDM). Map fields onto editables with `ObjectField_<field>` and `contextSource: DisplayPageItem`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Asset lists                   | `asset-list-entries.json`                                                                                | Array of `{ title, externalReferenceCode, assetTagNames, unicodeProperties: { classNameIds, query, orderBy } }`. Scope is the site only: no placeholder exists for the Global site, where company-scoped object entries live.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Object entries                | `object-entries/NN-<name>.json`                                                                          | `{ "objectDefinitionName": "<Object>", "object-entries": [...] }`, imported in file-name order. Used instead of `ecopulse-batch` because at first boot a batch imports entries before the new objects' permissions exist.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Journal articles              | `journal-articles/<name>.json` + `<name>.xml`                                                            | Give both `externalReferenceCode` and `articleId` to avoid `DuplicateArticleIdException`. Content is DDM XML, e.g. `<root><dynamic-element name="content" type="text_area"><dynamic-content language-id="en_US"><![CDATA[…]]></dynamic-content></dynamic-element></root>`. Reference documents with `[$DOCUMENT_URL:/site-initializer/documents/group/filename.png$]` (the full resource path; `DOCUMENT_JSON` and `DOCUMENT_FILE_ENTRY_ID` work the same way).                                                                                                                                                                                                                                                                                                                 |
| Taxonomy                      | `taxonomy-vocabularies/group/<vocabulary>.json`, categories in `<vocabulary>/`                           |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

Not read by Liferay: `site-initializer.json` (descriptive metadata; the brand wiring is in the master pages) and `expando-columns.json` values (the columns are created, but nothing sets or reads them). Search blueprints cannot be imported by a site initializer on standard DXP; they live in `ecopulse-batch` (see the Meridian skill).

## Re-running an initializer

If initialization fails or hangs on an existing environment, increment the site's `externalReferenceCode` (e.g. `ecopulse-site-v9`) and the extension's `id` in `LCP.json` to force a clean start.
